# Веб-приложение (`apps/web`)

Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, Recharts, Zod, Supabase (`@supabase/ssr`).
Компоненты UI написаны в стиле shadcn/ui (Radix + cva), без генерации через CLI.

## Запуск

```bash
cd apps/web
cp ../../.env.example .env.local   # заполнить NEXT_PUBLIC_SUPABASE_URL и NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
npm install
npm run dev                        # http://localhost:3000
```

Сначала примените миграции (см. `docs/SUPABASE_SETUP.md`). В Supabase Auth → URL Configuration добавьте `http://localhost:3000/auth/callback` в Redirect URLs, иначе ссылка подтверждения почты не сработает.

## Страницы

| Путь | Назначение |
|---|---|
| `/login`, `/onboarding` | вход/регистрация, создание бюджета и первого счёта |
| `/` | обзор: доходы, расходы, разница, сбережения, долги, остатки, платежи, график, категории, сравнение, последние операции, выводы по данным |
| `/transactions` | таблица (карточки на телефоне), поиск, фильтры, сортировка, пагинация, добавление/правка/удаление с подтверждением, импорт и экспорт CSV |
| `/analytics` | динамика по дням/неделям/месяцам, категории, сравнение периодов, постоянные/переменные расходы, прогноз, необычные расходы, дубликаты, цели |
| `/debts` | долги, прогресс, платежи, оценка даты закрытия |
| `/budgets` | лимиты по категориям, дневной лимит, «доступно для накоплений», цели |
| `/settings` | счета, категории, участники и приглашения, курсы валют |
| `/join?token=…` | принятие приглашения |
| `/api/fx/refresh` | обновление курсов (заголовок `Authorization: Bearer $CRON_SECRET`) |
| `/api/transactions/export` | экспорт CSV с теми же фильтрами |

Фильтры страниц хранятся в URL (`period`, `from`, `to`, `cur`, `user`, …).

## Где что считается

- Все деньги и проценты считаются в `src/lib/finance` (целые числа, без float) и покрыты тестами.
- Страницы читают данные только через клиент пользователя (RLS). Ключ `SUPABASE_SECRET_KEY` используется лишь в `src/lib/supabase/admin.ts` для записи курсов.
- Валюта операции берётся из счёта на сервере; курс фиксируется при сохранении и при правке не меняется, пока не изменены сумма, дата или счёт.
- Графики строятся по реальным операциям; без данных показываются пустые состояния.
- «Выводы по данным» на обзоре — факты, посчитанные кодом. Текстовые AI-сводки появятся на этапе 4.

## Ограничения этапа 3

- Работа с реальным Supabase отсюда не проверялась (сеть контейнера блокирует `*.supabase.co`): проверены типы, линтер, 121 unit-тест, SQL/RLS-тесты на локальном PostgreSQL, production-сборка и внешний вид графиков.
- Остатки счетов считаются по всей истории операций в приложении; для очень больших объёмов (десятки тысяч строк) их стоит вынести в SQL-представление.
- Фильтр «Участник» работает по автору операции (`created_by`).
- E2E-тесты Playwright не написаны: им нужен живой проект Supabase с тестовым пользователем.
