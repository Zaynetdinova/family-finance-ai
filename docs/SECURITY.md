# Безопасность

## Доступ к данным
- Все таблицы под RLS (`0002_rls.sql` и последующие). Браузер работает с publishable-ключом и видит только бюджеты, где пользователь — участник; роли owner/admin/member/viewer.
- Серверный ключ (`SUPABASE_SECRET_KEY`) используется только в `src/lib/supabase/admin.ts`: Telegram-бот, регулярные задачи, курсы, коды привязки, отвязка Telegram. Каждый запрос бота явно ограничен бюджетом привязанного пользователя; подтвердить или отменить операцию через бот может только её автор.
- Поля `telegram_user_id/telegram_chat_id` клиент изменить не может (триггер); привязка — только по одноразовому коду (хранится SHA-256, срок 15 минут).
- Приглашения в бюджет — одноразовые токены (хранится SHA-256), 7 дней, роль ограничена.

## Публичные эндпоинты
| Путь | Защита |
|---|---|
| `/api/telegram/webhook` | секрет `X-Telegram-Bot-Api-Secret-Token`, сравнение за постоянное время; повтор update_id отбрасывается |
| `/api/jobs/tick`, `/api/fx/refresh` | `Authorization: Bearer $CRON_SECRET` (≥16 символов, иначе отключены) |
| `/auth/callback`, `/login`, `/join` | Supabase Auth; `next` после входа — только относительный путь (нет open redirect) |
| остальное | требуется вход (proxy) + RLS |

## AI
- Модель только извлекает поля; ответ валидируется Zod, лишние поля и неверные суммы отклоняются, ничего не «чинится».
- Валюту, счёт, курс, суммы и разбивку платежа определяет код; неоднозначность → вопрос пользователю.
- Текст сообщения пользователя — данные, а не инструкции (это указано и в системном промпте; на запись это не влияет, т.к. решения принимает код).
- В отчётах AI-текст с числами, которых нет в посчитанных фактах, отбрасывается.
- AI не выполняет переводы и платежи и не меняет банковские счета — только ведёт учёт.
- Лимит 20 обращений к модели на пользователя за 5 минут; все обращения — в `ai_interactions` без секретов.

## Секреты
- Только переменные окружения; `.env*` в `.gitignore`; в репозитории и экспортах n8n секретов нет (проверяется тестом).
- Ошибки внешних API сводятся к коротким кодам; токены и тела запросов в логи не попадают.
