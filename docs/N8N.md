# n8n и регулярные задачи

## Архитектура

Вся бизнес-логика (расчёты, AI, запись в базу, идемпотентность) живёт в приложении. n8n — только **планировщик**: по расписанию вызывает защищённые HTTP-эндпоинты. Так workflow не содержат ни секретов, ни логики, а повторный запуск безопасен.

| Процесс из ТЗ | Где реализован |
|---|---|
| 1. Приём сообщений Telegram | Telegram → `POST /api/telegram/webhook` напрямую (без n8n: меньше звеньев, тот же контроль секрета) |
| 2. Распознавание через OpenAI | приложение, `src/lib/ai` (Structured Outputs + Zod) |
| 3. Валидация и подтверждение | приложение, `normalize.ts` + кнопки в боте |
| 4. Запись в Supabase | приложение, сервисный ключ, явная фильтрация по бюджету пользователя |
| 5. Предотвращение дубликатов | `telegram_updates` (update_id), уникальный `external_message_id`, `notifications_sent` |
| 6. Формирование отчётов | приложение, `src/lib/reports` |
| 7. Ежедневные и еженедельные сводки | n8n (каждый час) → `POST /api/jobs/tick` |
| 8. Ежемесячная аналитика | то же: 1-го числа отчёт за закрытый месяц |
| 9. Напоминания о платежах и лимитах | то же: по настройкам пользователя |
| Курсы валют | n8n (раз в день) → `POST /api/fx/refresh` |

## Эндпоинты

Оба принимают `GET` или `POST` с заголовком `Authorization: Bearer <CRON_SECRET>`. Без него — `401`. Если `CRON_SECRET` не задан или короче 16 символов, эндпоинты отключены.

**`/api/jobs/tick`** — вызывать раз в час (в любую минуту). Для каждого пользователя с привязанным Telegram по его часовому поясу:
- сводки (ежедневная / еженедельная / месячная) — в выбранный час и до конца того же дня, если запуск был пропущен;
- напоминания о платежах за N дней и о просроченных; предупреждения о лимитах (порог и превышение) — с 9:00 до 22:00.

Ответ: `200 {ok, recipients, sent, skipped, errors: []}`; `207`, если у части пользователей были ошибки (остальным всё отправлено); `503` — не настроены `TELEGRAM_BOT_TOKEN`/`SUPABASE_SECRET_KEY`.

Идемпотентность: перед отправкой создаётся строка в `notifications_sent` с уникальным ключом (`weekly:2026-W43`, `payment:<долг>:2026-10-25`, …). Повторный вызов в тот же час ничего не отправит. Если отправка не удалась, строка удаляется — следующий запуск повторит.

**`/api/fx/refresh`** — раз в день. Загружает USD→RUB и USD→ARS; повторный вызов в тот же день перезаписывает те же строки.

## Настройка n8n

1. **Credential** (Credentials → New → *Header Auth*):
   - Name: `Family Finance CRON_SECRET` (именно так — на это имя ссылаются workflow)
   - Header Name: `Authorization`
   - Header Value: `Bearer <значение CRON_SECRET из окружения приложения>`
2. **Импорт**: Workflows → Import from File → `n8n/family-finance-hourly-jobs.json` и `n8n/family-finance-daily-fx.json`.
3. В каждом workflow откройте узел **Config (edit app_url)** и укажите адрес приложения (`https://...`, без `/` в конце).
4. В узле HTTP Request выберите созданный credential (после импорта n8n попросит его привязать).
5. Нажмите **Execute workflow** один раз: в ответе должно быть `"ok": true`. Затем включите workflow (**Active**).

Ошибки: HTTP-узел повторяет запрос 3 раза; ответ не 2xx помечает выполнение как ошибочное (видно в Executions; можно подключить Error Workflow n8n для уведомлений администратору). Успешные выполнения не сохраняются, чтобы не копить данные.

## Без n8n

Любой планировщик, умеющий отправлять HTTP-запрос с заголовком:
- **cron-job.org** (бесплатно): URL `https://<app>/api/jobs/tick`, каждый час, Advanced → Headers → `Authorization: Bearer <CRON_SECRET>`.
- **Vercel Cron**: при заданном `CRON_SECRET` Vercel сам добавляет этот заголовок. В `apps/web/vercel.json` уже есть ежедневное обновление курсов. Почасовой `tick` на бесплатном тарифе Vercel не разрешён (только раз в день) — на Pro добавьте `{ "path": "/api/jobs/tick", "schedule": "5 * * * *" }`.

## Ручная проверка

```bash
curl -i -X POST https://<app>/api/jobs/tick -H "Authorization: Bearer $CRON_SECRET"
curl -i -X POST https://<app>/api/jobs/tick                     # должно быть 401
```
